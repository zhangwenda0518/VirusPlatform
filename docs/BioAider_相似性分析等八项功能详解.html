BioAider 八项功能详解

Similar Analysis（5）+ Download Tools（1）+ Conversion Tools（2）
依据：_bioaider_re/decompiled/ 反编译源码逐行核对 | 2026-09-11
读之前先知道一件事：「Remove High-Similar」和「Delete Low-Similar」用的是同一套贪心聚类骨架， 只是判据方向相反。看懂一个，另一个就懂了。下面第 2、3 节会把这套骨架讲清楚。

1Sequence Identity Matrix —— 成对同一性矩阵

输入已比对的等长 FASTA
选项① 矩阵类型：Single nt or aa / Combination nt and aa (nt/aa)
② Condense gap? Yes / No
③ 遗传密码表（仅 nt/aa 模式生效）
输出<前缀>_identity.csv（总是生成）
<前缀>_identity_used_for_heatmap.csv（仅 nt/aa 模式）

核心公式

单模式（Condense gap = No）: A = 相同位点数 − 双 gap 位点数 B = 不同位点数 Identity = A / (A + B) 单位 % Condense gap = Yes: Identity = A / (A + (B − 2 × inser / 3)) inser = 只有一侧是 gap 的位点数 → 把连续 3nt 的插入/缺失折算成 1 个错配 nt/aa 联合模式: 单元格 = "核苷酸% / 氨基酸%"（氨基酸先翻译再算）
⚠️ 这个口径和 SDT 不一样。BioAider 把单侧 gap 计入分母当错配； SDT（本平台 sdt_exact）把 gap 列整列排除。含 indel 的序列两者数值不同。
热图文件的三角约定：下三角 = 核苷酸，上三角 = 氨基酸。
本平台已实现等效功能并做过逐字节验证，详见 docs/BioAider_SDT同一性分析_逆向报告.html 与 _bioaider_re/sdt_identity.py。

2Remove High-Similar Sequence —— 去高相似（去冗余）

输入FASTA（Sequence Identity / Hamming 两种算法要求已比对，其余四种最好不要预先比对）
选项算法 6 选一；Similar threshold 0–100 的百分数
输出<前缀>_Reserved-seq__remove-HighSimilar.<ext> —— 保留的代表序列
<前缀>_classify record.txt —— 每条序列属于哪个簇（Classification / SeqName）

算法：贪心增量聚类（不是全对全）

代表集 = [] for 每条序列（按文件顺序）: for 代表 in 代表集（按加入顺序）: sim = 1.0 if 序列 == 代表 else similary_counter(算法, 序列, 代表) if sim >= 阈值/100: 归属到该代表 → 丢弃，记录 ClusterID，break if 没有归属: 加入代表集 → 保留
四个关键事实
  • 结果依赖输入顺序。是贪心算法，先到先得，换一个顺序结果就不同。 界面提示写的是"随机保留其中一条"，实际实现是确定性的——永远保留最先遇到的那条。
  • 是"首个匹配即归属"，不做传递闭包。所以 A 和 C 可能同属一簇， 即使 A、C 之间相似度低于阈值（只要各自都跟某个代表达标）。这是 CD-HIT 式的行为。
  • 阈值 = 100 时走另一条快速路径：不做相似度计算，直接比序列字符串是否完全相同， 即纯粹的精确去重。此时选哪个算法都一样——和手册描述一致。
  • 输出是"保留集"，被丢弃的序列只出现在 classify record.txt 里。

附带的"相似性矩阵"功能（右键菜单）

在窗口任意处右键 → Get similary matrix → 输入文件名 → 生成 <前缀><你输的名字>_matrix.txt，内容是所选算法下的全对全相似性矩阵。

注意：这个矩阵里的数值是 0–1 的小数（不是百分数），跟同一性矩阵的 % 口径不同。 另外它是真正的 O(n²) 全对全——几千条序列会很慢。

3Delete Low-Similar Sequence —— 去低相似（剔离群）

输入同上一项（FASTA + 算法 + 阈值）
输出<前缀>_Reserved-seq__remove-LowSimilar.<ext>
<前缀>_classify record.txt

骨架和第 2 项完全一样，唯一的差别是判据方向：

Remove High-Similar: if sim >= 阈值/100 → 丢弃（太像了） Delete Low-Similar: if sim < 阈值/100 → 丢弃（太不像了）

所以语义是：与已有代表都不够像的序列会被剔除，保留下来的代表集构成"彼此都够像"的核心。

实际使用要小心：由于是"扫到第一个不达标的代表就丢弃"， 一旦代表集里出现两条互相不相似的序列，之后几乎任何新序列都会跟其中一条不达标而被丢弃。 阈值别设太低，建议先小样本试跑、看 classify record.txt 的簇分布再放大。
顺便澄清一处文档不一致：示例目录里 Delete Low-Similar 的文件名是 seq__classify record.txt（双下划线），而当前版本代码生成的是 seq_classify record.txt（单下划线）——说明示例文件是更早版本产出的， 不要拿示例文件名当输出命名的依据。

4Repeat Fragment Search —— 重复片段搜索

输入文本框里直接粘贴一条或多条 FASTA 序列
参数Minimum length / Maximum length —— 重复基序的长度范围
输出写到你自己选定的目录（STEP 3）：每条序列一个 <序列名>_result.txt

算法

1. 枚举长度在 [min, max] 内的**所有子串**（去重，保持首次出现顺序） 2. 对每个子串：用正则找出它在原序列里的**全部出现位置**（1-based） 3. 出现次数 ≥ 2 才保留 4. Percentage = 出现次数 × 子串长度 / 序列总长

输出文件格式：首行 Qure sequence: <序列名>，然后表头 String / Position / Percentage，位置用逗号连接。

两个要注意的地方
  • 复杂度是 O(L²) 级别，长序列会非常慢。子串数量约为 L × (max−min+1)， 每个子串还要全序列正则扫描一遍。10 kb 的基因组配上 3–10 的范围就很吃力了。
  • 子串被当作正则表达式使用（re.finditer(子串, 序列)）。 纯 ACGT 没问题，但如果序列里有正则元字符（如 .、*），匹配会出错或语义变形。
输出会同时包含大量嵌套与重叠的短重复（比如 AA 在长序列里几乎必然重复）， 结果文件可能很长，需要自己按 Percentage 排序筛。

5Locate Protein in Nucleotide —— 蛋白定位回核苷酸

给定一段蛋白片段，找出它在编码基因序列中对应的核苷酸区段与坐标。

输入STEP 1：核苷酸 FASTA
STEP 2：氨基酸 FASTA
STEP 3：遗传密码表
输出<AA 文件名前缀>_locate_result.txt —— 定位结果日志
<输入目录>/Intercept(nt).fasta —— 截取出来的核苷酸片段

算法

对每条 AA 序列: 对每条 NT 序列: if AA名.find(NT名) != -1: ← 靠名字子串匹配配对 aa_full = translate(NT序列) i = aa_full 中 AA片段 的首次出现位置 若找到: nt_start = i × 3 + 1 nt_end = (i + len(AA片段)) × 3 截取 NT[nt_start-1 : nt_end] break（只取第一条配上的 NT 序列）
三个使用前提
  • 配对靠名字子串匹配：AA 序列名里必须包含 NT 序列名（AA名.find(NT名) != -1）。 两边名字完全无关就配不上，会静默跳过。
  • 只取首次匹配：如果同一段蛋白在序列里出现多次，只会定位到第一个位置。
  • 蛋白片段同样是按正则匹配的。蛋白序列里若有 *（终止密码子翻译结果）， * 在正则里是量词，会导致匹配错误甚至报错——用之前先把 * 去掉。

6Sequence Batch Download (NCBI) —— 序列批量下载

输入粘贴 accession 列表，每行一个（上限 180 条，界面有提示）
选项数据库：Nucleotide / Protein / Gene / Genome / All databases
输出没有文件输出
重要：这个功能不下载任何东西。
它的实现只有一行有效逻辑——把 accession 用 | 拼起来，套上对应数据库的搜索 URL， 然后调用默认浏览器打开这个搜索页：
https://www.ncbi.nlm.nih.gov/nuccore/?term=AY567487|AY994055|CQ870486|CS124012
剩下的检索、勾选、下载全都要你手动在网页上完成。
它省掉的只是"手动拼 URL"这一步，没有任何 API 调用、没有断点续传、没有格式选择。

对照：本平台的 ncbi_download 是真正走接口下载并落盘的，比它完整得多。

7File Merge —— 多文件合并

输入一个文件夹（界面有 File-paths preview 可先看会合并哪些文件）
输出<该文件夹>/merge.txt
递归枚举文件夹里**所有文件**（含子目录，无扩展名过滤） 逐个把内容追加写入 merge.txt，文件之间插一个空行
三个坑，都会真的踩到
  • 不过滤文件类型。文件夹里有图片、Excel、二进制文件也会被当文本读进来， 结果文件直接变成乱码。界面提示自己写了"输入文件夹中不要放与合并无关的其他任何文件"。
  • 输出写在同一个文件夹里 → 重复运行会自我包含。 第二次运行时，上一次生成的 merge.txt 也在文件夹里，会被一起合并进去， 文件越滚越大。每次跑之前先把旧的 merge.txt 移走。
  • 读写都没指定编码（open() 不带 encoding=）， 用的是系统默认编码。Windows 中文环境下处理 UTF-8 文件可能报错或乱码。

8Date converted to Decimal —— 日期转十进制

把采样日期转成"十进制年"，用于 tip-dating / 分子钟定年（BEAST、TreeTime 之类的输入）。

输入粘贴日期列表，每行一个；含 # 的行会被跳过（可当注释用）
输出<选定目录>/dates-decimal.txt，一行一个十进制数，顺序与输入一致

算法

按 [./_-] 切分日期字符串 3 段（年/月/日）: 闰年 → 年 + (该月之前的天数和 + 日) / 366.00000001 平年 → 年 + (该月之前的天数和 + 日) / 365.00000001 2 段（年/月）: 同上，但"日"按 1 算（即当月第一天） 其他情况 / 解析失败 → **原样返回输入字符串**
两点说明
  • 分母写成 365.00000001 / 366.00000001 是刻意为之—— 避免 12 月 31 日恰好算出下一个整数年，让年份区间闭合在半开区间里。
  • 闰年判断是朴素的 year % 4 == 0，没有处理"百年不闰、四百年再闰"。 1900 会被误判为闰年（实际不是）。对植物病毒样本来说年份基本在 1950 年之后， 只有 1900 这一个例外年份会踩到，影响可忽略——但如果要严格，自己改一下。
