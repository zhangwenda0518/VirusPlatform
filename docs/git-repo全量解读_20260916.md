#### A1. WMV6-phylogeography ★★★（3.3 MB，10 文件，无许可证）

**内容（`find` 实测，10 文件全列）**：

```
discrete_phylogeography/data/NP-wmv6-discrete-ucld-skygrid-glm.xml          ← 主角
discrete_phylogeography/data/NP-wmv6-discrete-ucld-skygrid-glm_combined_MCC.tree

```

**XML 实测特征**：`chainLength="100000000"`（1e8）；`skygrid` / `glmSubstitutionModel` /
`markovJumpsTreeLikelihood` 三组元素共 24 处（16+5+3）；127 条序列、27 个区划
（18 个中国省份 + 9 个国外，样本如 `mos172gb65361|Culex_globocoxitus|AUS|Point_Douro`
—— 数据实为**库蚊蚊媒病毒**，不是植物病毒）。

**对管线（virome_phylo_pipeline）的帮助**：
- **离散 + 连续两套完整 XML**：`utils/beast1_bridge.py` 目前生成 skyline/bdsky/constant；
  这两套可作为第 4/5 个模板（离散扩散 `multivariateTraitLikelihood`；
  连续扩散 `arbitraryBranchRates + onePGammaDistributionModel + flatGeoSpatialPrior(KML)`）。
  BEAST 数据段的叶性状 `leafTraitParameter`、rateIndicator 写法可直接对照。
- **`WuMV-6_phylogeography_predictors.ipynb` 是"迁移预测因子矩阵"的现成生成器**：
  它从区划多边形生成 origin/destination/land_borders/distance/flyways 五类成对预测因子矩阵
  （GADM/KML 数据源），正好补齐 `utils/geo_analysis.py`（RRT+TempMig）之后
  想做"GLM 迁移预测"的那一环。
- **`NP_traits_region.txt` 的 `ID|宿主|国家|地点` 四字段格式**可与管线的
  元数据/区划文件格式互相校验（管线用 `sample_id = Location/ID/date` 约定，注意口径转换）。
- ⚠️ 无许可证：**以"学结构、改配置"方式使用，不整文件复制**（XML 是配置不是代码，
  但出处应标注：Neijiang Normal University 相关论文仓库）。

**对「进化动力学」的帮助**：t-phylogeo 未来若接入 BEAST 引擎，这张 XML 是"离散扩散 + skygrid
共估计"的**最近完整样本**（2026 年仓），`markovJumpsTreeLikelihood` 正是"转移矩阵计数"的
贝叶斯版本——与平台 Fitch/RRT/RSPP 形成"简约法 → 贝叶斯法"升级路线图。

#### A2. flu_d_project ★★★（367 MB，8 个 XML，无许可证）

**内容**：`xml_files/` 下 8 个 XML：`2026_seg4_all`、`seg4.subsample_all`、`segment1-7.cds`，
全部 `chainLength=1e8`。

**已实测的硬核事实**：GLM 指标先验值 `0.032468221476108394` 在 **5 个 XML 中命中**
（`segment7:3091`、`seg4.subsample_all:2132`、`segment6:3121`、`2026_seg4_all:3292`、`segment1:2981`）——
该常数 = `1 − 0.5^(1/21)`，即 21 个成对预测因子下 BSSVS/rateIndicator 的指标先验概率
（`p = 1 − 0.5^(1/K)`）。这是 GLM 迁移分析**唯一容易被写错、且论文里通常不明写**的数字。

**对动力学的帮助（最高优先）**：
- 若平台 t-phylogeo 将来加"迁移预测因子（距离/边界/宿主作为协变量）"，
  这里给出完整的 `glmModel family="logLinear"` + `designMatrix`（origin/destination 成对列）
  + 指标先验 `1−0.5^(1/K)` 的**可发送配置样例**。
- 8 个 XML 覆盖"全量 / 降采样 / 单片段"三种数据策略（同一病原的 8 个变体），
  可学习"数据子采样对迁移推断的敏感性"这一分析套路。

**对管线**：`beast1_bridge.py` 若支持 GLM 模式，此仓是主要数学依据。367MB 主要是日志/树文件。

#### A3. MTBD-HPAIV_Japan ★★★（3.3 MB，9 个 XML，无许可证）

**内容（实测 9 个 XML 全列）**：`MTBD_Hosts_{2122,2324,2425}_Japan.xml`、

**对管线**：BEAST2 与 BEAST1 在管线里可以并存（不同 XML 生成器），留作远期。

## 4. 对「进化动力学」卡组的逐卡建议

### 4.1 现状基线

| 卡片 | 现在有什么 | AUDIT（`AUDIT_病毒浏览器与进化动力学_20260915.md`）记的缺陷 |
|---|---|---|
| `t-phylogeo` | Fitch 迁移重构（down-pass 已修）+ 转移矩阵 + RRT 置换检验 + RSPP 不确定性 + LSD2 | 「迁移计数无置信区间」（RSPP 已补） |
| `t-rtt` | 根到尾回归 + LSD2 定年 + bootstrap + 钟模型 | 「缺 date-permutation 检验；小样本 R² 放大 4.4–5.4×」 |
| `t-rdp` | 原生 RDP5 九方法 + 自研六方法检测 + 断点图 | 见 AUDIT P2/P3 各项 |
| 病毒浏览器「时空趋势」 | 198,819 条全库时空浏览 | — |

### 4.2 t-phylogeo ← 本批最值钱的三处（+ 1 项远期路线图）

1. **polio 14 表 → JSON schema（★★★）**：三个矩阵（mean/lo95/hi95）+ support + top_corridors
   + flow_partition + import_export + region_centroids 直接映射为结果面板 JSON
   （schema 草案见 §B1）。**先做这个**——它是"迁移矩阵"从"一张表"变成"带区间的科学结论"的
   最小闭环。
2. **import/export 图（★★）**：SARS 的 1/group_size 算法（B2，行号已锁）实现"哪些是引入、
   哪些是本地传播"；这是 t-phylogeo 目前完全空白的一格功能，且纯 Python 可做。
3. **方法学警告（★★）**：用 E1 drifting 的仿真结论给卡片加"数据条件检查"提示
   （方向性扩散/无历史样本 → 根位置与方向的推断风险）；这与已实现的 RRT p 值一起，
   构成"简约法自检 + 理论边界"两层防护。
4. （远期）**BEAST 引擎路线图**：离散模板=A1 WMV6，预测因子数学=A2 flu_d，
   BSSVS=A4 ebolavirus（CC BY 4.0 可自由用），链长预期表=§A5。
   MAPLE 的 `location_resolver` 功能面提示：「地名归一化」是上游必做的一步（自己实现）。

### 4.3 t-rtt ← 两条升级线

1. **TreeTime 三件套（★★★）**：D1 phymap 的 `[3] treetime`（分子钟 + `--clock-filter 4`
   离群去除 + `--coalescent skyline`）给出了"RTT 之上"的标准升级；
   TreeTime 是独立 Python 包（无 R 依赖），与平台 `resolve_years()` 年份口径可复用。
   配合 `--prune` 剪枝思路（D1 `[1]`）加"离群序列处理"。
2. **date-permutation 检验**（AUDIT 缺陷，仍是空白）：polio 的 `root_to_tip_diagnostics.csv`
   + phymap/ TreeTime 的日期随机化思路可组合实现；这是纯 Python 统计（打乱采样日期 →
   重跑 RTT → 零分布），预计半天工作量，**建议与 4.2 的 schema 一起排期**。

### 4.4 t-rdp ← 本批几乎没有帮助（要如实说）

27 仓 **0** 个 RDP/重组检测工具。唯一相关：B5 SCAR（重组感知**建模**）——
可作为 `mask_recombination` 之后的"重组敏感性"方法学参考（远期）。
E1 drifting 的"仿真-评估"范式可以借鉴为"**RDP 检出率仿真**"
（合成已知重组事件 → 测你的检测器召回率）——这是 t-rdp 现有测试可以升级的方向。

### 4.5 动画/可视化升级路线（spreadgl2 > phylomovie > phylowood）

- **首选 C1 spreadgl2（MIT）**：deck.gl 9.3.7 的 TripsLayer/ArcLayer 动画 +
  e2e 性能预算（fps 测试）；平台前端已是 Web，技术同构，借鉴成本最低。
- C2 ggphylogeo：连续 HPD 层叠的**图型**标准（R 实现，图型可 Python 复刻）。
- C3 phylomovie：GIF 逐帧 + conicfit 椭圆（R；仅思路参考）。
- C5 sclipman 的 59MB data.json：**保持分段加载**的反面证据。
- 病毒浏览器侧：MAPLE 的 `location_resolver` 提示"地名归一化"服务化是通用需求。
