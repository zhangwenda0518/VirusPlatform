1SeqFormat Convertor —— 格式转换

四种序列格式之间互相转换，12 种有向组合全覆盖。

输入单个序列文件，格式为 Fasta / Nexus / Paml / Phylip 之一
选项源格式下拉框 → 目标格式下拉框；
Data type（Nucleotide / Protein）只在目标格式选 Nexus 时可点，其他情况置灰
输出Fasta→Fasta：<前缀>_trans.fasta
其余：<前缀>.nex / .pml / .phy / .fasta
实现细节：所有转换都走 FASTA 中转——先 x_to_fas() 再 fas_to_x()。 所以 Nexus→Phylip 实际是 Nexus→Fasta→Phylip，中间若有 FASTA 表达不了的信息会丢。
另外 Fasta→Fasta 的输出名（_trans）跟其他转换的命名规则不一致，容易找不到文件。

2Sequence Vary —— 一个窗口 10 种序列处理

左侧是单选按钮列表，每个选项对应一种处理，输出文件名各不相同：

处理输出文件（前缀_ 之后再拼）
Extract SeqTaxon_seq_taxon.txt —— 只导出序列名，去掉 >
Uniform Seqname Length: N_seq_len.<ext> —— 序列名截断到前 N 个字符
Reverse_reverse.<ext>
Reverse complement_reverse_complement.<ext>
U to T_U_to_T.<ext>
T to U_T_to_U.<ext>
SeqLength + GC%_SeqLength_GC.txt —— 表头 SeqName / Lenth / GC%
Translation to AA_translate.<ext> —— 需选遗传密码表
DNA_Protein_DNA_PROT.<ext> —— 同时输出 >名_nt 和 >名_aa
Extract codon sitesCodon (1+2, 3) → _codon_1-2 + _codon_3
Codon (1,2,3) → _codon_1 + _codon_2 + _codon_3
值得注意的实现细节
  • 反向互补用的是手写 IUPAC 互补表（含 R↔Y / M↔K / B↔V / D↔H / S↔S / W↔W / N↔N）， 并且按序列里有没有 T 决定用 DNA 表还是 RNA 表——所以 RNA 序列也能正确处理。
  • GC% 计算前会先去掉 - 和空格，即 按非 gap 位点计算。
  • DNA_Protein 用的是 gap_DNA_genetic_godes_transle（带 gap 的翻译版本）， 保证氨基酸序列与核苷酸的 gap 对齐——这点和 Translation to AA 用的普通翻译函数不同。
  • 可选 25 张遗传密码表（标准码 / 脊椎动物线粒体 / 酵母线粒体 / 纤毛虫核 …）。
  • Extract codon sites 会先校验序列长度是否为 3 的倍数，不是就报错退出。

3SequenceID Rename —— 批量改序列名

输入任意文本文件——序列文件或系统发育树文件都行；
外加粘贴一张对照表：旧名称 + TAB + 新名称，一行一条
输出<前缀>rename.<ext>
读取整个文件为字符串 → 逐行 replace(旧名, 新名) → 整体写回
三个必须知道的坑
  • 是纯子串替换，没有词边界保护。规则 seq1 → A 会把 seq10 也改成 A0。
  • 规则按顺序执行、会级联。若同时有 A→B 和 B→C， 原来叫 A 的会被改两次，最终变成 C。
    规避办法：新名不要和任何旧名重合。
  • 对照表每行必须恰好含 1 个 TAB，否则报 "The format is error ... at line N" 并中止。

4Split Sequence Fragment —— 按坐标切片段

输入FASTA 序列文件
两种模式 Different range：粘贴表格 序列名 + TAB + 起始 + TAB + 结束， 每条序列用各自坐标（此时下方文本框可用）
Equal range：直接填一组起止坐标，所有序列统一（表格置灰）
输出<前缀>split.<ext>

坐标是 1-based、含首含尾：源码里是 seq[start-1 : end]。

注意：Different range 模式下序列名必须完全相等（u1 == seq_name）才匹配； 不在表里的序列会被静默丢弃，输出文件里根本不出现——不会报错，也不会保留原样。 另外每条序列只取第一条命中的规则。

5Combine Gene —— 多基因串联 ★

把多个已比对的基因文件水平拼接成一个整体，用于多基因联合建树。

输入一个文件夹（内含多个已比对的基因 FASTA）；
点 "Load file" 后，文本框里会列出所有文件路径——这个顺序就是串联顺序，可手工调整
选项Data type：Nucleotide / Protein
输出格式（可多选）：Fasta / Nexus (Sequential) / Nexus (Interleave)
输出写在输入文件夹里：
Combine.fasta
Combine(Sequential).nex
Combine(Interleave).nex

算法

  1. 以第一个文件的序列集合和顺序为准（taxon 集合由它决定）
  2. 后续每个基因按序列名查找对应序列，依次拼在后面
  3. NEXUS 输出里自带分区块，基因名取自文件名（去扩展名）：
begin sets; charset gene1=1-450; charset gene2=451-900; partition Names = 2:gene1,gene2; set partition=Names; end;

Interleave 模式按每 100 字符一块换行排列。

两个需要注意的地方
  • 补 gap 的实现有隐患。某个基因里找不到某条序列时，源码执行的是 ww.popitem() —— 从该基因的序列字典里随机弹一条出来，拿它的长度补 gap， 而且会把这条序列从字典里删掉。
    如果该基因内序列长度不一致，补出来的 gap 长度就是错的；而且后续再遇到缺失，候选池已经少了一条。
  • 分区块是 MrBayes 风格（set partition=）。IQ-TREE 需要的是 charpartition mymodels = ...，两者不通用——要喂 IQ-TREE -p， 得另外用 Partition-Model Make（Evolution ▸ Phylogeny）生成分区文件。
还有个容易忽略的点：文本框里的文件顺序来自 os.listdir()， 不保证按文件名排序（取决于文件系统）。跑之前务必确认一下顺序对不对—— 串联顺序错了，分区坐标就全错。

6Visual Gene Extractor —— 按关键词批量提序列

输入FASTA 文件（拖拽或点击加载）
+ 一个或多个关键词，每行一个，多个关键词取并集
输出<前缀>_extract_result.fasta

界面右侧会列出文件里所有序列名，方便你对照着填关键词；下方是提取日志。

细节
  • 匹配是子串匹配（name.find(关键词) != -1）且大小写敏感。
    填 gene 会同时命中 geneX 和 mygene——要精确匹配就填全名。
  • 输出时会把序列名里的 lcl| 前缀去掉。
  • 右侧那份「GenID → 已提取基因」的汇总日志用的是硬编码的 GenBank 命名正则 （匹配 >lcl..._cds）。非 GenBank 风格的名字这份日志会静默失败 （整段包在 try/except 里），但序列提取本身不受影响。

7Sequential Extraction Text —— 按列表顺序提取

输入FASTA 文件 或 普通文本文件（用 Data type 单选切换）
+ 一个字符串列表，每行一个
输出<前缀>extra.<ext>
for 列表里的每个字符串: 在文件里从头扫描，找到第一条「名称/行内容包含该字符串」的记录 输出它，然后 break（每个字符串只取第一条命中）

关键点是输出顺序 = 你给的列表顺序，而不是文件里的原始顺序。

两种模式的输出差异
  • Fasta file 模式：输出 >序列名 + 序列。没找到就什么都不输出。
  • Normal text 模式：输出整行。没找到会写一行 <字符串>\tNULL ——这个哨兵很有用，能一眼看出哪些没匹配上。
典型用途：把一批序列按你指定的顺序重排（比如对齐到参考数据集的排列）， 或从大文件里按清单抽取子集。

8Viral *.gb file parser —— GenBank 批量信息提取

输入单个 .gb 文件（可含多条记录）
参数Threads（进程数）
Max.num.seqs in iterative（分片读取阈值，默认 10000；值小省内存但慢）
选项Export sequence to table —— 额外导出一列序列
Influenza virus —— 额外提取流感病毒的蛋白 translation
Classification extraction —— 按分类层级建目录、把每条 gb 分门别类存好
输出<前缀>strain_information.xlsx（28 列）
若勾选分类提取：按 界/门/纲/…/属/种 建目录，每条毒株一个 .gb， 外加每个目录一份 starin summary.txt

提取的字段（28 列）

Accession · Version · Length · Genomic · Topology · Updated date， 然后是 12 级分类（Biological / Realm / Kingdom / Phylum / Class / Order / Suborder / Family / Subfamily / Genus / Subgenus / Species），再是 Organism · Strain · Isolation source · Metagenome source · Host · Collection region · geo_loc_name · Collection date · Title（勾选后再加 Sequence）。

实现要点
  • 用 multiprocessing.Pool 多进程并行；按 max_num_seq 分片流式读取控内存。
  • 先把记录按 // 切开，再把换行统一替换成 &&，然后跑正则。
  • 同时抓 country 和 geo_loc_name 两个字段—— 这是 V1.727 针对 NCBI 把 country 改名为 geo_loc_name 做的适配。
三个已知瑕疵
  • 分类学列可能错位：程序自己的提示里就写了 "Taxonomy information may be misaligned with the column names due to some absent annotation"。 gb 文件里分类注释缺级时，后面所有分类列会整体前移。
  • 输出文件名 starin summary.txt 拼写错误（应为 strain）。
  • 分类提取以 Version 作为索引键；缺 Version 的记录会被跳过，不会进目录。

9Fast Annotation —— 快速注释 / 批量抽基因

输入已比对的 FASTA，且 参考序列必须放在第一条
参数表格输入，可增删行：Gene name + Start string + End string
输出每个基因一个 FASTA：<输入目录>/<基因名>.fasta
<输入目录>/qury_index_table.csv（Gene name, Start index, End index）
在第一条（参考）序列上: start_index = 参考序列.find(起始字符串) + 1 end_index = 参考序列.find(结束字符串) + len(结束字符串) 把这套坐标套用到**所有序列**：seq[start_index-1 : end_index]
前提与风险
  • 起始/结束字符串必须在参考序列里唯一——这是硬要求，否则定位到错误位置。
  • 坐标是在参考序列上算的，然后套到所有序列上。这依赖"序列已比对且 gap 一致"这个前提； 如果参考序列本身有缺失、或比对质量差，切出来的片段会错位。
  • 官方建议：序列相似度越高，注释越准。
  • 输出直接写在输入文件所在目录（不是子目录），基因名就是文件名—— 基因名里若有 / 之类的字符会出问题。

10Ambiguous Base Edition —— 模糊碱基 + 提前终止密码子校正 ★

这个功能最有意思，也最复杂。目的是为 PAML 等分析准备干净的序列。

输入基于密码子方式对齐的 FASTA
输出<前缀>_clean.fasta —— 校正后的序列
<前缀>_hamming_distance.csv —— 中间产物，全对全 Hamming 距离矩阵

第一步：模糊碱基校正

  1. 先算全对全 Hamming 距离矩阵（O(n²)，程序日志里自己都写了 "This step will take a long time"）
  2. 找出每条序列里所有 IUPAC 简并碱基的位置 （R Y M K S W H B V D N 共 11 种）
  3. 对每个简并位点，取最近的 10 条邻居序列（按 Hamming 距离排序，跳过自己）
  4. 看这 10 条在该位点是什么碱基，取众数
  5. 如果众数落在该简并码允许的碱基集合里 → 用众数；否则 → 用允许集合里的第一个
例：某位点是 R（允许 A/G） 邻居 10 条里多数是 A → 替换为 A 邻居 10 条里多数是 C → C 不在 {A,G} 里 → 回退为 A（允许集合的第一个）

第二步：提前终止密码子清理

  1. 按密码子切分；若序列末尾本身就是终止密码子（TAG/TGA/TAA），则排除最后一位密码子
  2. 扫描内部终止密码子，发现时从同密码子位置的其他序列借碱基：
位置取材范围
靠前（前 3 条序列）取第 i+1 ~ i+4 条序列在同一密码子位置的密码子
中间取 i−1、i−2、i+1、i+2 四条
靠后取 i−1 ~ i−4 四条

然后对这 4 个候选密码子取众数替换掉终止密码子。

我发现的一个 bug（用之前要知道）
候选列表 st_codon_to 在双重循环外面初始化，循环内只 append、从不重置。 所以处理第二个及以后的提前终止密码子时，候选池里还留着前面位点的候选—— 众数统计会被污染。一条序列里终止密码子越多，偏差越大。
（这解释了为什么作者建议只对相似度高的序列集使用该功能。）
作者与使用建议
该功能由 Xiyue Wang 贡献（源码内署名 "Yusy"，版本 V0.3），界面上还写着 "Special thanks to the developer of Yusy!"。
官方给出的两条建议（来自 Update_record.md）：
  • 单条序列的模糊碱基占比不宜超过 2%；
  • 遗传距离远的序列不适合做这种校正——因为算法本质是"从近邻借碱基"， 近邻越远，借来的碱基越不可信。
