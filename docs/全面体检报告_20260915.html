二、修复的功能缺陷

用户可见i18n 缺失 18 个键，界面直接显示原始键名

现象
专项分析页「系统地理分析」卡片的标题显示为 tk.phylogeoH2； 同页「重组检测 / 时间信号与定年」的描述显示为 tk.rdpDesc、tk.rttDesc； 公共病毒组页 5 个联动图表标题显示为 vx.chYearT 等；样品批量扫描提示同理。
根因
这些键在 i18n.js 的 zh/en 字典里都没有定义。 运行时 t(key, null) 在字典缺失时返回 key 本身， 而 applyI18n() 拿到非 null 值就写进元素 —— 于是中文与英文界面 都会把标题替换成键名字面量。
影响
用户在中文界面下就会看到乱码般的键名，属于一眼可见的界面缺陷。
修复
补齐 zh/en 各 17 个键（含缺失的 4 个 tk.*、5 个 vx.ch*T、 5 个 sc.*/dz.*）。
验证
新增 tests/_verify_i18n.js：用 Node 加最小 DOM 桩加载 真实 i18n.js 跑 applyI18n，修复前 10 处元素被写成键名， 修复后 0 处；契约审计的「代码使用但字典未定义」由 18 降为 0。

健壮性管道阶段执行顺序依赖调用方传入顺序，报告可能先于组装执行

现象
_stage_execution_order(['report','primer','orfa','orf','assembly']) 返回 ['report','assembly','primer','orf','orfa'] —— 报告排在最前。
根因
拓扑排序只保证「已选阶段之间的硬依赖」先跑，同层保持调用方顺序； 而 report 的 deps 只声明了 kvsuite， 覆盖不了「报告天然最后」这类顺序约定。
影响
若有调用方传入乱序的阶段列表，报告会在组装之前生成， 生成出来的报告里就缺少组装/注释结果。当前前端传参顺序正确， 因此该问题尚未暴露，属于潜在缺陷。
修复
同层改为按 STAGE_ORDER 定序（它本身是拓扑合理的全序）。 完全逆序传入也能恢复正确顺序，按默认顺序传参的行为不变。

显示不一致示例结果列表的产物计数虚高

现象
「专项分析」各工具卡的示例结果列表显示的文件数与点进去看到的 文件列表对不上（实测 45 处差异）。
根因
/api/examples 的 n_files 取 manifest.json 里 files 数组的长度（生成器跑完那一次的 快照），而详情接口 /api/examples/<module> 是 遍历真实目录。为控制仓库体积清理过大文件（run.log、 *.fastq.gz、SPAdes 中间产物）后，快照就落后于实际。
修复
列表计数改为与实际列表同源 —— 统一按文件系统统计 （新增 _count_files()）。26 个模块的计数与详情列表 逐个比对全部一致。

测试可信度缺开发依赖时测试误报失败

现象
tests/_check_kvchain_ui.py 在未安装 playwright 时抛 ModuleNotFoundError 并被记为 FAIL。
根因
同目录其他浏览器探针（_it_download_ui 等）都实现了 「无浏览器时自动 SKIP 并返回 0」，唯独这个脚本没有。
影响
没装开发依赖的环境整批测试变红，掩盖真实结论。
修复
改为优雅 SKIP 并给出安装提示，与其他探针约定一致。

三、测试基础设施修复（本机环境）

关键发现：项目自带的绿色版 Python 目录下有 python312._pth， 该文件存在时 Python 进入 isolated 模式，sys.path 完全由 _pth 决定 —— python -c "..." 时不含当前工作目录。 而 python 脚本.py 时 sys.path[0] 是脚本所在目录，所以正常。

这导致三处「用 -c 起临时服务」的测试永远起不来服务 （日志里是 No module named 'app'）：

  • tests/_check_kvchain_ui.py
  • tests/_it_global_ctx_ui.py
  • tests/_it_nav_responsive.py

已在三处的 -c 代码开头显式注入 sys.path.insert(0, ROOT)。 修复后 _check_kvchain_ui.py 首次完整跑通（此前从未真正执行过它的检查项）。

四、审计工具本身的改进

巡检工具若自身有误报，红灯就不可信。本轮修掉三处：

问题说明修复
模块可达性扫描范围过宽 os.walk(ROOT) 会遍历 3rd/（5224 个第三方 .py）、 run/、_bioaider_re/，既拖慢又因第三方代码里 非 raw 字符串的 \s/\w 刷出一片 SyntaxWarning，淹没真问题 排除这些目录，只审计平台自有代码 —— 审计从数秒降到 1.8 秒，警告归零

动态拼接前缀被当成未定义键 t('tk.' + x[0], x[1]) 中的 'tk.' 被当成一个完整键 跳过以 . 结尾的前缀，并在输出中单独说明

此外删除了 app-compare.js 中定义后从未使用的死变量 cmp （它指向一个后端并不存在的 /compare/<name> 路由）。

改进后跨层契约审计输出：✔ 无硬性差异； main.py selfcheck 由「存在未就绪项」变为 ✔ 自检通过。

五、真浏览器巡检：一个环境坑与解法

在本机执行真浏览器巡检时发现：同一个 chromium 进程内连续访问多个页面， 会在第 3～6 页之间随机段错误（headless shell 与完整 chromium 均如此）。 经诊断：单页独立访问始终正常、与具体页面无关、系统内存充足（63.8 GB 总量）， 属于累积状态问题而非页面缺陷。

解法：给页面巡检脚本增加 逐页独立进程 驱动（已设为默认模式， --fast 保留单进程连续访问）。改造后 21 个页面全部通过：

  • /、/annotation、/build、/cds-export、/download、/genome、/help、/hostpredict、/hostremoval、/logan
  • /meta、/orf、/pipeline、/primer、/results、/samples、/settings、/submit、/tasks、/tools、/vexplorer

新增工具把「验收」从人工判断变成可复跑

  • dev_tools/pyz_vs_source.py —— 把 PYZ 里每个 Virus_Platform_Core.* 模块与磁盘源码逐字段比较 （co_code / co_names / co_varnames / co_flags…），并递归进嵌套 code。 这比原先"打印符号表再人工看"硬得多：函数体内的改动也能覆盖。 配套 tests/_selftest_pyz_cmp.py 做灵敏度自检 （同一源码两遍 → 无差异；常量/运算符/新增函数/函数内部改动 → 均能报出）， 确认比较器不是恒真。

打包卫生spec 的 datas 把工具残留打进了分发版

  • 问题：webapp/templates/.mimosa（编辑器 hook 缓存， 5 KB）随 webapp/ 整棵拷贝进了 _internal/webapp/。 datas 不支持 ignore 参数，写 (目录, 目标) 就是原样全拷。
