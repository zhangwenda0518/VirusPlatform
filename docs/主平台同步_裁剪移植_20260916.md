  **有组无入口等于没有** —— 只有组没有导航项，用户还是只能手敲 URL。
  标签与进化平台同名组一致（复用拆分时留在 i18n.js 里的 `nav.g.phylodyn`，
  **零新增键**）。
- 比较基因组（seqprep / align / treebuild / sdt）与 BEAST 产物导入**仍只在进化平台**。

## 5. 顺带修的两个真缺陷（`tests/_check_pages_console.py`）

页面巡检的默认模式是"每页一个子进程"，父进程靠子进程的结论判定。原实现有**两处**问题，
合起来等于**永远报绿**：

1. **判据恒真**：单页模式的 `if '--page' in sys.argv: main()` **丢掉了返回值** ——
   子进程无论页面坏成什么样都 `exit 0`，而父进程只看 `returncode`。
   → 改成 `sys.exit(main())`。
2. **子进程 stdout 读不回来**：父进程 `subprocess.run(..., text=True)` 按本地代码页（GBK）
   解码，而平台自己的模块会把子进程 stdout 重配成 **UTF-8**（`/settings` 加载全量数据时
   打印的 3771 字节自检报告），读线程抛 `UnicodeDecodeError` → stdout 变空 →
   那次巡检连"结论行"都没有。→ 改成 `encoding='utf-8', errors='replace'`，
   并把**子进程自报的末行结论（`OK ` / `BAD `）** 作为主判据、`returncode` 作兜底；
   两者都不满足一律记 ✘（静默截断从此变成可见红灯）。

**负对照（证明修好了）**：把子进程结论强行改成 `BAD` 的临时副本跑一遍 →
父进程 `rc=1` 并逐页打印 ✘；原实现在同一副本上会打印"全部页面 ✔"。

## 6. 口径边界（写文案时不许越界）

- 分带驱动：`rssp.corridor_support`，标签固定「RSPP bootstrap 支持率（非贝叶斯后验）」。
  主平台**没有**贝叶斯 ASR / BEAST 三口径，措辞不许借来用。
- RRT 是 **BaTS 式简约法替代**（打乱 tip 区划标签重跑 Fitch 置换检验），不是 VirPhyKit 的
  贝叶斯 RRT —— 回答同一个科学问题，但不能声称是它的实现。
- 三分类阈值口径与进化平台一致：**运行内分位带**（边数 <6 或距离退化时退回 500 / 3000 km
  固定阈值），`thresholds.src` 如实回报 `run-quantiles` / `default(n<6)` / `default(degenerate)`。
- 方法学提醒（卡片顶部静态文案）：方向性扩散 / 缺古样本时方向与根位重建误差更大，
  方向性结论先看 RRT 是否显著。
