二、本次补充的功能细节

2.1 Sequence Identity Matrix 的完整口径（新增源码依据）

09-05 的文档把它记作"同 SDT 口径"，这一条需要更正。两者对含 indel 的序列会给出不同数值：

口径分母单侧 gap 列
BioAider所有非"双 gap"列计入分母，算作错配
SDT（本平台 sdt_exact）仅"双方都有碱基"的列整列排除
BioAider:  identity = (相同位点 - 双gap位点) / (相同位点 - 双gap位点 + 不同位点)
SDT:       similarity = 100 × (1 - dist / (aln_len - gaps))   # gaps = 任一序列为 gap 的列

另有两个 BioAider 独有的选项，本平台目前没有：

  • Condense gap：A / (A + (B - 2 × inser / 3))， 把连续 3nt 的插入/缺失折算成 1 个错配，避免一个密码子缺失被记成 3 个错配。
  • Combination nt and aa：单元格输出 "核苷酸%/氨基酸%"， 并额外产出一份热图专用表（下三角 = nt，上三角 = aa）。

2.2 Remove High-Similar Sequence 的 6 种算法

底层是 textdistance 库，六选一：

算法需要预先比对适用性评价
Sequence Identity是推荐，与同一性矩阵同口径
Hamming是快，但等长假设强
Smith-Waterman否O(n²)，慢
Levenshtein否编辑距离，对核酸意义有限
Damerau-Levenshtein否同上，额外处理换位
Needleman-Wunsch否O(n²)，慢
建议：不要照抄这套实现。BioAider 是纯 O(n²) 全对全比较， 几千条序列就会卡死。你们已经打包了 3rd/tools/mmseqs， 应该先用 MMseqs2 聚类粗筛，再在簇内用 identity 精筛—— 上万条也能跑，且结果可解释。

三、建议吸收（按优先级）

第一档：有明确科研场景，建议做

  1. 多基因串联 + 分区文件（对应 combine_seq + partition_make）

    分段基因组（双生病毒 DNA-A/DNA-B、番茄斑萎病毒、呼肠孤）多基因座建树刚需。 输出 FASTA + NEXUS 分区文件，直接喂 IQ-TREE -p。

    BioAider 的分区文件生成器（partition_make）只出分区、不做串联， 且 IQ-TREE / MrBayes 两套格式都支持，可直接参考其格式模板。

  2. 参考集按 identity 阈值去冗余

    你们建树用的参考池 / NCBI 集合常含高相似冗余。先去冗余再建树， 能显著缩短 IQ-TREE 时间并让树更干净。建议做成 quicktree 的前置开关， 或独立 dedup 轻工具。

  3. 系统发育格式互转（nexus / phylip / mega）

    目前 convert 只处理 .sra 和 FASTQ。 但 iqtree/mrbayes 输入、外部分析脚本对接都常需要这些格式。 纯文本转换，百行级工作量。

第二档：顺手能补，成本极低

  1. 序列 ID 批量重命名 + 映射表

    NCBI 下载的序列名动辄 NC_001367.1 Tomato mosaic virus isolate ...， 建树图里糊成一团。重命名并导出"原名 → 新名"对照表，保证结果可回溯。

  2. 模糊碱基（IUPAC）校正

    PAML / 密码子选择压力分析的前置清洗。BioAider 的做法是 在密码子比对中把 R/Y/W/S/K/M 等按规则校正或剔除。 建议挂为 align 或 identity 的前置选项。

  3. 同一性矩阵的 indel 口径选项

    不必照搬 BioAider 的公式，但值得在 identity 里加一个下拉： SDT 口径 / BioAider 口径 / 压缩 gap，并在结果页注明当前口径。 审稿人很爱问这个，提前把口径摆明比事后解释省事。

第三档：不建议吸收

  • 那 4 种 O(n²) 编辑距离算法（Levenshtein / Damerau-Levenshtein / Smith-Waterman / Needleman-Wunsch）—— 对核酸序列意义有限，且慢。
  • PySide2 桌面 GUI 架构 —— 你们的 Web + 任务工厂已经更优。
  • 外部工具"插件化安装"（Not-installed → Add）—— 你们全内置 + 自动探测，更省心。
  • 简易实验记录生成器 —— 与平台定位无关。

四、一个额外发现：示例缺"参数说明"

BioAider 的每个 Example/ 子目录都带一份 parameter_note.txt， 写明该功能的参数含义与推荐取值。
本平台 examples/ 有 18 个样例文件（example_tmv.fasta、 example_tree.nwk 等），但 零个说明文件—— 用户看到一堆样例却不知道该配什么参数。

这是投入产出比最高的一项：不需要写代码，只要给每个样例补一段 "这个文件配哪个工具、参数怎么填、期望输出长什么样"。建议直接照 BioAider 的 parameter_note.txt 形态来，中英双语对齐你们的 i18n。
