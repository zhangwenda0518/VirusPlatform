## 1.4 `phylogeo.py`（2,322 行）—— 从 B 裁剪移植的**旧快照**

模块 docstring 自述范围：

> 系统地理分析（本地实现）：FASTA → 建树（NJ/FastTree）→ **Fitch 最大简约**把区划性状
> 重构到内部节点 → 迁移矩阵 / 标注树 / 逐叶状态表。
> 三个**可选**统计层（默认关）：`region_permutation_test`（区域随机化）/ `rssp_bootstrap`
> （根状态不确定性）/ `lsd2_dating`（LSD2 严格钟定年）。
> 地理层：逐样本经纬度 + 区划落点（样本点中位数 > 坐标表质心 > 内置质心表）→
> 迁移事件按 haversine **三分类**（Direct/Indirect/Distant/Unresolved）+ 走廊聚合；
> **MOTP 迁移随时间分箱**；**后验权重分带**（驱动源 = RSPP 方向支持率）。

与 B 的 `phylogeo.py` 的精确关系（AST 逐函数哈希，忽略空白）：

仅 A 有        0   ← A 是 B 的真子集

### 逐阶段功能

#### A0 `stage_prep(aln, meta, tree, out_dir, date_col=None, trait='region', date_trait=None, build_tree=True)` — line 239

- 叶名读取口径与 `phylogeo.safe_first_token` 一致；**< 3 条序列直接拒**；重名序列告警
- 日期列 / 区划列**自动判定**（`date/sampling_date/decimal_date/time/collection_date/日期`；
  `year/decimal_year/sampling_year/年份`）
- 逐序列取日期与区划：元数据列 → 前缀/包含兜底 → **FASTA 头回退**（`pg._header_traits`）
- **匹配率必须 100% 才算通过**，不通过时把未匹配名单（前 50）原样列出 ——
  文档注明红线：TreeTime 名字对不上会**静默算错**
- 返回值含 `date_source_mix` / `state_source_mix`（每个值来自哪一列/哪一段）

#### A1 `stage_clock(prep, out_dir, methods=('treetime',), ..., reroot='least-squares', keep_root=False, confidence=True, time_marginal='only-final', clock_filter=None, drt_perm=20, drt_seed=42, do_drt=True, lsd2_seq_len=None, treedater_seq_len=None, treedater_ltt=False, rng_seed=0, timeout=3600)` — line 499

- **并列**跑 1–3 条定年通路（`treetime` / `lsd2` / `treedater`），**不平均、不取最优**
- `clock_stats.tsv` 带 `method` 列并排写
- 接口产物固定 `clock/timetree.nwk`，**由 TreeTime 产出**（唯一同时给时间树 + 节点年代 +
  地理/天际线/祖先序列的通路）；TreeTime 未选或失败则退用 LSD2 时间树并在报告写明
- 内置 DRT（日期随机化检验）与数值合理性闸门 `_gate_clock_stats`

#### A2 `stage_phylogeo(clock, prep, out_dir, trait='region', sampling_bias_correction='auto', cross_check=True, rssp_bs=0, seed=0, confidence=True, timeout=3600)` — line 957

- **TreeTime mugration（ML）与平台 Fitch 简约并列**，`corridors.tsv` 出 `ml` / `fitch` 两列
- 实测（RSV 209）：总数 70 vs 71（差 1.4%），但**逐走廊方向差别很大**
  （`NCS→KOR` 24 vs 2、`CCD→NCS` 3 vs 17）→ 文档写死"两列都要给，不许只留一个，不许相加"
- `events_year.tsv`（`Year, Origin, Destination`，借 Mugration-Analysis）→ 让"迁移随时间"
  **不再必须依赖 BEAST MCC 树**
- **采样偏倚检查默认开启**（`sampling_bias_correction='auto'`）
- 可选"换 divergence 树对拍"（枝长口径敏感性）

#### A3 `stage_coalescent(clock, prep, out_dir, n_skyline=None, gen_per_year=50.0, rng_seed=0, timeout=3600)` — line 1192

- TreeTime `--coalescent skyline`，**独立再跑一遍 clock**（因为 skyline 会改变速率估计：
  RSV 209 实测 3.07e-4 → 2.45e-4），这一份速率单独记在 `coalescent_report.json`
- 明确声明：`skyline.tsv` 的上下界是 TreeTime 的**近似区间（±2 SD of the LH）**，
  **不是**贝叶斯 95% HPD；`N_e` 绝对标度取决于 `--gen-per-year`（默认 50）

#### A4 `stage_ancestral(clock, prep, out_dir, marginal=False, method_anc=None, rng_seed=0, timeout=3600)` — line 1272

- TreeTime `ancestral`，喂**替换单位**的树（`clock/divergence_tree.nwk`）
- 平台此前只有 BEAST 产物导入路径，这一条是**本地从无到有**

#### A5 `stage_report(stages, out_dir, params=None)` — line 1330

- `run_summary.json`（每个产物记 **sha256 前 16 位**）+ `config.resolved.json`（实际生效配置）
  + `RUN_REPORT.md`（人读版：用了什么方法、口径提示、警告、产物清单）
- 借 pathogen-phylo-genomics-pipeline 的溯源做法

#### 编排 `run_pipeline(aln, out_dir, meta=None, tree=None, stages=None, **kw)` — line 1536

- 阶段依赖：`clock`←`prep`；`phylogeo`/`coalescent`/`ancestral`←`clock`；缺依赖的阶段
  **跳过并记原因，不静默**
- `prep_in` / `clock_in` **续跑**：给上一轮已落盘的阶段结果字典（至少含 `outputs`），
  阶段间只认文件，不做反序列化猜测
- `should_cancel` 只在阶段之间检查（单个阶段内部不打断，因为子进程各自有 timeout）

### ① `treetime_ml.py`（1,469 行）—— TreeTime ML 引擎

**定位**：轨道 A 的 ML 引擎；与 `phylogeo.lsd2_dating`（严格钟）、`treedater.py`（松弛钟）**并列而非替代**。
**外部引擎**：TreeTime（`subprocess` 调用，**顶层无子命令形式**）。

> ⚠️ 模块头实测：`treetime clock --confidence` / `--time-marginal` / `--coalescent` 全都报
> `unrecognized arguments` —— 子命令是"缩水接口"，**定年一律走顶层形式**。
> ⚠️ 三条通路速率**不可互相替代**：476 叶 H3N2 实测 treedater **3.7e-3** / TreeTime **3.12e-3**（差 7–9%）/ LSD2 **2.10e-3**。

| 函数组 | 函数 | 作用 |
|---|---|---|
| 环境 | `clean_env` / `find_treetime` / `check_tt_env` | 找入口（环境变量 → platform.json → 3rd → Scripts → PATH，**找不到不抛异常**）；体检秒回 |
| 写表 | `write_dates_csv` / `write_states_csv` / `write_weights_csv` | 表头**必须含 `name`**（否则 `parse_dates` 抛 `MissingDataError`） |
| 解析 | `nexus_tree_newick` / **`parse_annotated_newick`** / `iter_pre` / `tree_distances` / `node_dates_from_branches` | 自带状态机解析 `[&mutations="C131T,T367C"]`（**NEXUS 注释里有逗号**，`phylogeo.parse_newick` 会在注释里断句）；产出与 `phylogeo` 节点**同构**（多一个 `attrs`） |
| 解析 | `parse_clock_txt` / `parse_gtr_txt` / `parse_confidence_csv` / `parse_skyline_tsv` / `parse_branch_mutations` / `parse_homoplasy_stdout` | `confidence.csv` 里的状态是**字母 A/B/C**，必须用 `GTR.txt` 的 `Character to attribute mapping:` 翻译；拿不到 mapping **不许猜** |
| 走廊 | `count_corridors` / `corridors_table` | ML 与 Fitch **并列成表**（不混排名、不合并计数） |
| 子命令 | `run_clock` / `run_mugration` / `run_ancestral` / `run_homoplasy` | 四个子命令全接（`arg` 未接，平台已有 RDP5） |
| 对拍 | `leafset_key` / `cross_check_corridors` | **用"该节点覆盖哪些叶"当键**：mugration 会把内部节点重命名成 `NODE_0000123` 且两次运行编号不一致，按节点名对齐会静默错位 |
| 体检 | `suggest_sampling_bias_correction` / `audit_clock` / `audit_mugration` | 采样偏倚系数 `(1−Σpᵢ²)/(1−Σtᵢ²)`；**时间信号未过 DRT 时不给定年结论** |

> ⚠️ 模块头"第五个坑（最要命）"：**喂哪棵树，结果差一倍**。RSV 209 同一份数据，
> `timetree.nwk`（枝长＝年）给 **70** 次迁移 / mu 0.0255；`divergence_tree.nexus`
> （枝长＝替换/位点）给 **139** 次 / mu 79.9。拓扑相同，差的是枝长。

### ② `rtt_drt.py`（588 行）—— 时间信号的**显著性检验**

**定位**：`#t-rtt` 的 AUDIT 缺陷修复件。
**外部引擎**：无（纯 Python）。

> ⚠️ 模块头：平台原先只报 `root_to_tip()` 的**最大** R²，再拿固定阈值 0.5 判断。
> 但"取最大"＝在 ~2n−3 个候选根位上取**极值** —— 零假设下这个最大值同样被抬高，
> AUDIT 实测放大 **4.4–5.4 倍**：按 0.5 判，8 叶误判 **23.5%** / 12 叶 7.0% /
> 20 叶 0.5% / 30 叶 0%。而 8–20 叶正是病毒数据集的家常便饭。
> **DRT 的解法不是换阈值，而是造零分布**（把日期在 tip 之间随机置换 N 次），
> 阈值是数据自己的分位数，不再依赖叶数。

| 函数 | 作用 |
|---|---|
| `tree_geometry(tree_path)` | 一次算好每个候选根位的 `{叶名: 根距}`（候选＝某条枝的中点，与原 `root_to_tip` 搜索空间逐字一致） |
| `rtt_fit(dists, year_by_leaf, min_tips)` | 固定根位下的 OLS，返回 R²/slope/points（公式与 `phylogeo.root_to_tip` **逐字相同**） |
| `rtt_root_scan(...)` | 把**所有**候选根位的 R² 摊开（诊断用，"取最大"与"不搜索"差多少） |
| `date_randomization_test(tree, dates, n_perm=20, seed=42, rooting='optimize')` | Duchêne et al. 2015；`rooting` 两口径：`'optimize'`（每轮重根参与零分布）/ `'asis'`（固定根，只变日期映射，语义更干净） |

### ③ `bsp.py`（417 行）—— 贝叶斯天际线的读取/复算/绘图

**定位**：对应 VirPhyKit `src/BSP/`（BSP-Viz）。已确认上游是**纯绘图器，不是估计器**
（输入一张算好的 TSV，输出 PDF，且 x 轴写死 `xlim=c(1974,2016)`）。
**外部引擎**：无。

| 函数 | 作用 | 关键点 |
|---|---|---|
| `effective_sample_size(vals)` | ESS（Geyer 1992 初始正序列，Tracer 同族） | 取到 ρ_k + ρ_{k+1} < 0 截断；钳在 `[2, n]`；白噪声自检 ESS ≈ n |
| `read_skyline_table(path)` | 读 `Time/Lower/Median/Upper` | **原样转发不重算**（Lower/Upper 是别人算好的，引用须写明"经 Tracer/上游导出"） |
| `skyline_from_beast_log(log, burnin=0.1, ci=0.95, time_scale='auto')` | 从 BEAST BSP 日志算 | 每段 popSize **后验分位数是精确的**；但**时间轴是近似**（均匀溯祖假设，`time_axis='approx-uniform-coalescent'` + warnings） |
| `write_skyline_table(res, out)` | 写成与上游**同格式**的 TSV | 用 `%.10g` 而非 `%.6g` —— 6 位有效数字 round-trip 会**对不上**（测试抓到的） |
| `render_pdf(res, out, direction, color, secondary_axis, xlim)` | matplotlib 出 PDF/PNG | x 轴**自适应**（上游写死 1974–2016） |
| `audit_skyline(res)` | 页面体检 | 不抛异常 |

### ④ `mjrm.py`（910 行）—— MJRM 生成 + **审计** + **解析**

**定位**：BEAST1 Markov jump 计数。
**外部引擎**：BEAST 1.x（**模块自身不启动任何进程**）。
**需 BEAST 产物**：生成/审计 → 否（要 XML 模板）；解析 → **是**（tab `.log`）。

| 函数 | 作用 |
|---|---|
| `state_order_from_xml` / `traits_from_xml` | 读 BEAST **权威状态序号** `<generalDataType><state code=…>` |
| `build_matrices` / `build_rewards` | 与 VirPhyKit `function_mmj.wrtcfg()/wrt_rewards()` **逐字对齐** |
| `insert_into_template(template, traits, with_log=True, log_every=1000, trait_order='state')` | 插矩阵 + rewards，**并补上让计数真正输出的 `<log>`** |
| `audit_mjrm_xml(xml_path)` | **跑 BEAST 之前**检查这份 XML 到底能不能产出计数（三类问题：哑配置 / 矩阵顺序错位 / rewards 与矩阵自相矛盾） |
| `make_dating_config` / `build_pair` | 一次生成**定年版**（只靠序列似然）与**迁移版**两份 |
| `parse_beast_log` / `jump_matrix_from_log` / `write_jump_csvs` | 日志 → 逐路线均值/中位数/95% 区间 + **各区划停留时间**，落 `_routes.tsv` / `_matrix.tsv` / `_dwell.tsv` |

> ⚠️⚠️ 模块头实测（服务器 BEAST 1.10.4）：
> **VirPhyKit 自带的 `PVS_with_matrix.xml` 是"哑配置"** —— 插进去的指示矩阵被声明了，
> 却没有任何 `<log>` 引用它们。真跑 2×10⁶ 步，主日志 **125 列里 0 个 `A-to-B` 计数列、0 个 `_reward` 列**。
> 用 `ancestralTreeLikelihood` 挂 MJRM 也不行（`javap` 实测该类**一个 Jump 方法都没有**），
> 改成 `markovJumpsTreeLikelihood` + 接进 `<log>` 后 **37 列计数立刻出现**（30 路线 + count + 6 reward）。
>
> ⚠️⚠️ **状态序**：`<attr name="Region">` 的**首现顺序不是** BEAST 的行列下标。
> 实测 PVS 示例：attr 首现序 `AS,OC,EU,ME,NAm,SAm`，BEAST 真实状态序 `AS,EU,ME,NAm,OC,SAm`
> → VirPhyKit 按前者铺矩阵，`AS-to-OC` 那个矩阵的 1 落在 (0,1)＝**实际是 AS→EU，标签名不副实**。
>
> ⚠️ **插入锚点**：模板里 `<!-- END Ancestral state reconstruction` 有 **5 处**，
> 按"取第一个匹配"插（VirPhyKit `process_xml` 的写法）会把矩阵插到**另一个 likelihood 里**；
> 后果不报错，而是 BEAST 跑完**只吐 `c_Region.count[1]` 一列、30 条路线全不见**，比报错难查得多。
> 本模块只在目标元素**内部**取**最后一个**锚点。

### ⑤ `mot.py`（413 行）—— MCC 树的 route×year

**定位**：对应 VirPhyKit `src/MOT/`。**外部引擎**：无（Biopython `Bio.Phylo`）。**需 BEAST 产物**：**是**（MCC 标注树）。

分箱公式（与上游逐字）：`end = ceil(rootheight) − ceil(height)`；`start = end − floor(length)`；
某枝事件写入 `[start+rootyear, end+rootyear]` 的**每一个年份** →
**矩阵累加是「事件 × 跨越年份」，不是事件数**。

| 函数 | 作用 |
|---|---|
| `parse_node_states(comment, known_states)` | 四层回退：`max.set` → 任意 `<X>.set` → `location={}` → 逐状态键 |
| `name_year(name)` | 取**最后一个 `_` 段**按浮点解析 |
| `parse_mcc_tree(path)` | NEXUS/Newick + 节点表 |
| `mot_matrix(tree, info, dates, include_diagonal=False, min_prob=0.0, root_year=None)` | route×year 矩阵 + 可靠性诊断 |
| `write_csvs(res, out_dir, prefix='migration')` | `migration_over_time.csv` + `migration_yearly_summary.csv` |

> ⚠️ 模块头列出**原版的 4 个静默错误**（都是 2026-09-16 用 VirPhyKit 自带示例实测出来的）：
> ① 性状名只认 `location=` 一种 → **它自己的例子上 0/417 节点、0 事件**（期望 1133）；
> ② `tip_year` 的 `(\d{4})$` 抓到小数尾巴（`…_2008.58197` → **8197**）→"最新采样年 9863"、年份轴荒谬；
> ③ 把 `X_to_X`（原地不动）也算进矩阵 —— VirPhyKit 示例矩阵总计 **2483 里有 1350 是"没迁移"**；
> ④ 取 `max(后验)` 后**不看置信度**，后验平坦的节点被当成确定状态、**凭空造出迁移**。
>
> ⚠️ 另有两处平台侧实测坑：`_parse_comment` **绝不能 `strip('{}')`**（会把最后一个键的收尾 `}`
> 也剥掉 → MTT_MCC.tre 341 个节点只成功 185）；NEXUS 里**带引号的标签 Bio.Phylo 会连引号一起留下**
> → 按叶名查表**静默 0 命中**。
>
> ⚠️ **时间标度自检**：MOT 年份轴的前提是枝长以"年"为单位。实测 PVS/RSPP 那几棵替换率尺度的树
> 推出根年 **1324**（采样年在 2010 前后）→ 报"年份轴不可用"。

### ⑦ `beast_io.py`（855 行）—— BEAST 产物接入层

## 3.3 ★ 口径冲突清单（合并时最危险的部分）

同一科学问题，两边会给**不同的数**：

| 科学问题 | A | B | 可比？ |
|---|---|---|---|
| **有没有时间信号？** | `R² ≥ 0.5` 硬阈值 | DRT 日期随机化检验的经验 p（阈值 0.05） | ❌ B 注释实测：R² 硬阈值小样本误判率 **8 叶 23.3% / 12 叶 3.3% / 20 叶 1.7%**，DRT 稳定在名义 5% |
| **换了几次区？** | TempMig 分支-年矩阵：每条分支对跨越的每个日历年 +1，状态取 MCC 树 **MAP 注解** | A2：`corridors.tsv` 里 **`ml`（ML 点估计）与 `fitch`（最少变化数）并列两列** | ❌ 不是同一统计量。B 实测 RSV 209：总数 70 vs 71，但 `NCS→KOR` 24 vs 2、`CCD→NCS` 3 vs 17 |
| **根在哪、多确定？** | `RSPP-Viz`：读 BEAST 根注解的**贝叶斯后验** | `rssp_bootstrap`：**对可比对列重抽样 + Fitch** 的 bootstrap 支持率；A2 另给 TreeTime **ML 边际概率** | ❌ 三种量，B 代码注释专门警告"ML 边际概率 ≠ 贝叶斯后验" |
| **松弛钟速率？** | `trees.treedater_ltt`（自研 R 调用） | `treedater.py`（真 treedater + CoV + parboot） | ⚠️ 同一 R 包，调用口径不同，需实测对拍 |
| **LTT 斜率？** | 自研 `log N ~ t` 回归 | treedater `parboot` 真 LTT | ❌ A 文档自己写"只是净多样化的近似" |
| **Ne(t)？** | 只画你给的 Tracer TSV / BEAST log（log 口径组界按"等区间数 × 逐样本根高"**近似**） | A3：TreeTime `--coalescent skyline` 直接估 Ne(t)（上下界是 ±2 SD **不是 HPD**）；`bsp.py` 另给每段 ESS | ❌ 近似绘图 vs 模型估计，且两者都**不是**贝叶斯 HPD |
| **转移矩阵年轴？** | `mostcurrentyear` = **第二大去重叶年**（复刻 VirPhyKit 抗极端新近样本） | `mot.py` 有独立**时间标度自检** | ⚠️ 年轴定义不同 |
| **降采样抽哪几条？** | `seed` 留空 → **不可复现** | `seed` 留空 → 固定 `20260915` | ❌ A 跑两次结果不同 |
| **MJRM 用了几个状态？** | 按**用户输入序**生成矩阵；reward 块按字母序 | 按 XML 里 `<generalDataType><state code=…>` 的**真实行列下标**（文档：那才是 BEAST 的行列下标，不是 `<attr>` 首次出现序） | ⚠️ 若 XML 状态序与用户输入序不同，A 的矩阵会**错位** |

**唯一天然一致的数字**：两边 `region_permutation_test` 的 p 值（函数逐字相同，
`p_low = (1 + #{零分布 ≤ 实测}) / (N + 1)`，双尾都给）。
但前提是喂进去的 tip 区划标注一致 —— 标注来自 `_header_traits` / `match_states_and_years`，
**这两个函数两边已经不一样了**，所以实际也可能不同。

### 3.3.1 ★★ 复刻 VirPhyKit 的双刃剑：A 忠实地复刻了参照实现的**错误**

这是本轮清点里最重要的发现。A 的方法学基准是「与 VirPhyKit 逐字节/逐格对拍」，
但 B 用**真实 BEAST 1.10.4** 跑过参照实现，发现 VirPhyKit 的示例产物本身有硬伤：

| # | 问题 | VirPhyKit 的实际行为（B 实测） | A 的做法 | B 的做法 |
|---|---|---|---|---|
| 1 | **MJRM 状态序错位** | PVS 示例按 `<attr name="Region">` **首现序** `AS,OC,EU,ME,NAm,SAm` 铺指示矩阵；而 BEAST 内部行列下标来自 `<generalDataType><state code=…>`，真实序是 `AS,EU,ME,NAm,OC,SAm` → 标着 `AS-to-OC` 的那个矩阵，1 实际落在 (0,1)＝**AS→EU**，**标签名不副实** | 矩阵按**用户输入序**铺；`tools.html` 的占位符就是 `AS,OC,EU,ME,NAm,SAm`（＝错误的那套）；`phylodyn_kit.py` **全文不出现 `<state code>`**，即从不读 BEAST 权威状态序 | `mjrm.state_order_from_xml()` 读 `<state code>`；`trait_order='state'` 为默认，`'file'` 只留给"要和旧产物逐字节对拍"并附警告 |
| 2 | **MJRM 是"哑配置"** | 插进去的 `A-to-B` 矩阵被声明了，但**没有任何 `<log>` 引用它们**，`<markovJumpsTreeLikelihood>` 开标签也没有 `rewards=` → 真跑 2×10⁶ 步，主日志 **125 列里 0 个计数列、0 个 reward 列** | `mjrm_insert()` **只插矩阵 + `<rewards>`**，不补 `<log>` | `insert_into_template(with_log=True)` 顺手补上让计数真正输出的 `<log>`；并给 `audit_mjrm_xml()` 在**跑 BEAST 之前**拦三类问题（哑配置 / 顺序错位 / rewards 自相矛盾） |
| 3 | **插入锚点歧义** | `process_xml()` 按"取第一个匹配行"插入 | `mjrm_insert()` 取**第一个** `</markovJumpsTreeLikelihood>`，再回溯其上紧邻的 END 注释 | 文档实测：PVS 模板里 `<!-- END Ancestral state reconstruction` 有 **5 处**、`<markovJumpsTreeLikelihood>` 开标签在另一处；取第一个匹配会插进**另一个 likelihood**，后果**不报错**，而是 BEAST 跑完只吐 `c_Region.count[1]` **一列**、30 条路线全不见 → 本模块只在目标元素**内部**取**最后一个**锚点 |
| 4 | **对角线口径** | 矩阵把 `X_to_X`（原地不动）也算进去；示例矩阵总计 **2483 里有 1350 是"没迁移"** | A 的 TempMig `row_keys` 含 `a==b` → **默认含对角线**（复刻 VirPhyKit，A 文档称"107 年 × 25 方向逐格零差异"） | `mot.mot_matrix(include_diagonal=False)` **默认只出真迁移**，`=True` 才与 VirPhyKit 逐格对拍 |
| 5 | **未看节点后验置信度** | 取 `max(后验)` 后不看置信度 → 后验平坦的节点被当成确定状态，**凭空造出迁移**（父 0.35 判 A、子 0.39 判 B 就记一次） | A 的 `node_state()` 也是取 MAP，**无阈值过滤** | `mot_matrix(min_prob=…)` + **可靠性诊断**（内部节点最大后验的分布直方、低于阈值的节点数） |
| 6 | **采样年解析** | 原版 `(\d{4})$` 抓小数尾巴：`CCD_AB622861_2008.58197` → **8197** → "最新采样年 9863"、年份轴荒谬 | A 的 `_tip_years()` 用 `rsplit('_',1)[-1]` 再 `float()` → **避开了小数尾巴**（这点 A 与 B 一致） | `mot.name_year()` 取最后一个 `_` 段按浮点解析；另加"不能用裸 `(\d{4})`"的坑（PEDV 叶名登录号被命中 → 769 条叶静默拿到假年份 5468） |
| 7 | **性状名解析** | 原版只认 `location=` / `Location.set=` / `Location="…"`；而 VirPhyKit 示例树用 BEAST 原生逐状态格式 → 原版**在它自己的例子上 0/417 节点、0 事件**（期望 1133） | A 的 `detect_trait()` 会探测 `max` / `K.set` / `K.prob`，**能处理** VirPhyKit 示例的 `max` 形式 | 四层回退：`max.set` → 任意 `<X>.set` → `location={}` → 逐状态键 |

> **含义**：A 的「逐字节/逐格一致」证明的是**复刻保真度高**，不证明**结果正确**。
> 在 MJRM 这条线上，A 把参照实现的两个硬伤（#1 状态序、#2 哑配置）一起复刻了；
> TempMig 那条线则把对角线口径（#4）复刻了。
> **合并时若保留 A 的 MJRM 卡，至少要补 `<log>` 引用 + 用 `<state code>` 校正状态序**，
> 否则用户拿到的 XML 跑完 BEAST 是一条计数列都没有的。

### 3.3.2 判据的统计成熟度差异

| | A | B |
|---|---|---|
| 时间信号判据 | `strong_signal = r2 >= 0.5`（硬阈值） | `date_randomization_test` → `verdict ∈ {pass, fail, inconclusive}` |
| 零分布 | 无（`_perm_test_r2` 只对 R² 打乱日期，**不搜根位**） | 日期置换 + **根位搜索参与零分布**（`rooting='optimize'/'asis'/'optimize_once'` 三口径，统计含义不同） |
| 阈值来源 | 固定 0.5 | 数据**自己的分位数** |
| 功效保护 | 无 | **功效不足时不给 `fail`**：最小可达 p = 1/(1+n_valid) > α 时判 `inconclusive` 并算出"需要多少次置换" |
| p 值口径 | 无 | 经验 p + North et al. 2002 的 **+1 修正**；**刻意不采用**参照管道的"百分位 ≥95%"（实测 n_perm=20 时 rank 口径实际 α≈9.5%，n_perm=100 时 ≈5.9%） |

## 3.5 结论

1. **两边不是同一份内容的两个拷贝，是两套独立实现。**
   全库同名函数只有 6 个（`_read_table`/`_walk`/`find_rscript`/`_node`/`_num`/`_rec` 这类小工具）。

2. **唯一同源的是 `phylogeo.py`，而且 A 那份是旧快照。**
   A = B 的真子集（60 ⊂ 80），A 缺 B 的 6 处缺陷修复 + 20 个功能函数。
   **这是目前最实际的隐患**：A 上跑 VirPhyKit 命名的数据集会整片判未命中；
   月日级采样会被压成整年；截断树会 MemoryError。

3. **能力互补而不是重复。**
   A 独有：数据接入四来源、VirSpaceTime 时空绘图、**区域随机化三口径**、VirPhyKit 逐格一致的 TempMig。
   B 独有：全链编排、DRT 判据、免 BEAST ML 地理、祖先序列、同塑性、BEAST 导入/交接、import-export、定年溯源。

4. **A 当前有 5 处实读发现的缺陷**（见 §1.5），其中 4 个未定义的 JS 函数
   正好落在本轮要合并进 `t-pdbeast` 的那几张卡上（导出按钮 / 输入类型切换 / 填入 RRT 卡），
   合并时应一并修掉。

5. **★ 最需要注意的一条：A 的「与 VirPhyKit 逐字节/逐格对拍」保真度很高，但参照实现本身有硬伤。**

### 3.6.2 断点①（**P0，已修**）：explorer 自家导出包**吃不下**

A 的 explorer「导出 VirPhyKit 输入包」默认 `date` 列是**小数年**（`2008.58197`），
而接收入口 `phylodyn_kit.validate_date_str` 只认严格 ISO。实测：拿**自家**真导出包
（209 条全小数年）走 `import_from_zip` → **整包被拒**，只抛一句
「没有一条序列通过校验」——**报错完全不指向真因，上下游当场断开**。

修法（`Virus_Platform_Core/phylodyn_kit.py`）：

| 位置 | 改动 |
|---|---|
| `validate_date_str` | 加 `allow_decimal=False` 开关（**默认仍严格**，树侧调用方行为不变） |
| `decimal_to_iso`（新增） | 小数年 → ISO，`date_to_decimal` 的**精确逆**（同 365.25 口径，往返 <1e-6 年；精度损失 ≤1 天） |
| `validate_dataset` | 传 `allow_decimal=True`；命中小数年即 `dict(r, date=decimal_to_iso(...))` **折算入库** |

**为什么必须折算而不是原样透传**：小数年在自家管线 `to_decimal_year(strict=True)`
里会被错读 **+0.46 年**；数据集保持**单一 ISO 口径**才安全。
实测修后：真导出包 **209/209 全收、issues=0**、`2008.58197 → 2008-08-01`。

### 3.6.3 断点②（**已修**）：TreeDater-LTT 速率**符号为负**——未定根的树

`_check_phylodyn_example.py` §13 报 `rate = −3.49e−03`，断言红。三步取证
（探针 `run/_zz_td_probe*.py`）：Example 的 `h3n2_na_500.nwk` 是**未定根**的 ML 树
（**根三分叉**），而未定根树的"根到端距离"**物理上无意义**：

| 定根策略 | 斜率 | R² |
|---|---|---|
| 原样（未定根，三分叉） | **−3.49e−3** | 0.85 |
| **最老样本**作外类群 | **+3.82e−3** | **0.990** |
| 中点定根 | +1.28e−3 | 0.27 |

同树 TreeTime 给 +3.11e−3 / R²=0.986 → 定根后**完全同量级**。
修法（`phylodyn_trees.treedater_ltt` 内嵌 R）：
`if (!is.rooted(tre)) tre <- root(tre, outgroup=names(which.min(sts)), resolve.root=FALSE)`；
根节点索引改用 `length(tip.label)+1`（重定根后 `edge[1,1]` 不保证）。
**已定根的输入树行为不变**；`rtt_r2` 落进 `TD_summary.txt` 与返回值并被断言 `>0.9`。
R 侧实测：`rate=0.00380856 / rtt_r2=0.98963`。
